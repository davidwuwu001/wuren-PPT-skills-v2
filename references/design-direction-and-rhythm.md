# 每份课件的设计方向与整套节奏

## 1. 每次制作先做的设计判断

先读原稿和可用素材，回答：这份课件给谁看？现场讲解还是会后阅读？主要希望观众理解、感受或采取什么行动？哪些原图、原话或数据应该成为主角？用这些答案决定方向。

在读完内容并理解原图后，先为本次课件构思最多 3 个明显不同的方向，再向用户简明说明每个方向的视觉层级、典型构图和适用原因，推荐一个并等待用户选择或组合。差异应体现在信息排列、文字尺度、图文关系和阅读节奏，不只换背景色或字体。不要让用户先描述专业设计术语，也不要只给抽象风格名。当前请求已明确具体方向时不重复询问；用户明确要求直接做时，由 AI 自行选最合适的方向并说明假设。

以下是方向起点，可以组合或按内容另定，不能变成新的固定模板：

| 方向 | 内容适配信号 | 主要构图手段 |
|---|---|---|
| 编辑叙事 | 家庭故事、案例、理念分享 | 非对称图文、大引语、故事与旁注；图片和原话优先 |
| 清晰推演 | 方法培训、业务解释、决策 | 线索到结论、关联步骤、并列对照、主次分栏；关系由位置体现 |
| 温暖对话 | 家长沟通、学生体验、情感理解 | 提问与回应、留白、温和字形；有意义的场景IP可参与 |
| 证据聚焦 | 汇报、复盘、研究与分析 | 原始证据、关键数据、图表与解释；用字号与分组表达权重 |
| 现场共创 | 练习、工作坊、互动课堂 | 任务与作答区、步骤提示、讨论焦点；留出现场使用空间 |

五仁品牌紫可以作为标题、强调或章节底色；不要求每页大面积紫底。其他颜色仍按主技能的语义色板使用。保持中文字体角色，不照抄外部项目的西文字体和配色。品牌识别不依赖每页重复装饰条。

## 2. 在同一个 slide-plan.json 中记录决定

新计划的 `deckBrief.styleProfile` 增加：

- `designDirection`：这份课件的具体方向，避免只写“高级”“简约”。
- `designRationale`：为什么适合本次内容和受众；可简述未选另一方向的原因。
- `motif`：有意义的共同视觉线索，如“线索→需要→回应的连接关系”；也可以明确写“以字体与对齐建立统一，不加装饰母题”。不能只写“统一紫色短线”。
- `rhythm`：整体节奏及明暗、密度变化的用途；不强制轮换，也不靠插入空洞过渡页凑变化。

每页增加 `narrativeRole`（该页在讲述中的作用）、`visualFocus`（观众第一眼看什么），并落实 `layoutVariant`。字段是生成依据，不能只写在JSON、实际仍调用同一种网格。

## 3. 单页构图与整套节奏

- 先确定视觉主角，再组织支撑内容。原图、引语、关系、数据和问题不必都被塞进卡片。
- 顺序信息有方向与连接；比较信息成对对齐；故事允许场景与原话并置；平级要点才考虑列表或卡片。
- 普通内容页、重点页和呼吸页应有力度区别。根据叙事转折选择浅色、深色或图片主导，不机械一深一浅。
- 连续几页采用同一主体结构时，重新判断是否有内容理由；有意的案例系列可以保持一致，但至少让画像、原话、分析与结果体现不同的信息角色。不要用新增页数、删减内容或随机换色来制造变化。
- 一页少量有意义的文字，可以用排印成为主角；不要求每页配图、图标、IP或装饰形状。留白不需要填满。
- 禁止默认套用“标题＋短线＋等大圆角卡片＋右下角IP”。其中任何元素有内容理由时仍可用，但不能整套自动重复。
- 根据真实图片构图，而不是先画满文字再硬塞素材。保留原图要求与逐页IP适配规则继续生效。

## 4. 生成实现与交付边界

在批量生成前，为两类差异最大的已有内容页确定构图（例如原图证据页与案例分析页），再将共同字体、网格与留白规则展开到其余页。方向选择是制作前唯一的选择环节。选定后，构图对比是内部规划，不自动生成样张、截图或要求再次批准。

代码可以复用品牌和文本工具，但必须读取实际构图决定。不要把 timeline、compare、caseStory 全部分派到同一个 cards 函数，也不要改个类型名却输出完全一样的画面。

方向选择后保持生成成功即交付的约定，不增加第二轮审批。保持默认的 PptxGenJS 可编辑 PPTX；不引入默认 HTML 成品、浏览器动画、部署、强制渲染检查或每页必须用图的要求。

## 5. 借鉴来源与适配范围

检索日期：2026-10-14。以下为方法参考，用自己的表达整理；不复制模板、源码或第三方品牌资产。后续制作可直接使用本地规则，不必每次重新联网研究。

| 来源 | 采用的经验 | 在五仁的适配 |
|---|---|---|
| [Huashu-Design（本机技能）](../../huashu-design/SKILL.md)及其幻灯片参考 | 先理解叙事位置、观看距离和情绪；内容主角影响画面；避免默认卡片与无用填充 | 自主选择方向，保留五仁品牌和交付约定 |
| [Frontend Slides](https://github.com/zarazhangrui/frontend-slides/blob/main/SKILL.md) | 通过有实质差异的方向探索设计；内容和已有图像共同决定结构 | 用针对本课件的简短方向介绍供用户选择，不强制生成样张 |
| [归藏 PPT Skill](https://github.com/op7418/guizang-ppt-skill/blob/main/SKILL.md) | 叙事规划和整套页面节奏配合；同套设计保持秩序，主体结构随角色变化 | 按原内容规划强弱与明暗，不引入其模板或运行时 |
| [Anthropic PPTX 指南](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md) | 视觉主次、对比和布局变化；避免机械的标题装饰线 | 采用组织原则，不沿用其西文字体、配色或强制每页用图规则 |

Frontend Slides、归藏的仓库分别标示 MIT、AGPL-3.0。Anthropic PPTX 是公开可读的参考，不将其等同于可任意复制的开源模板。这里只整合一般设计方法。
